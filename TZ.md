# Garlic — ТЗ

Личный таск-трекер и хранилище заметок в виде графа. Основной режим работы — бесконечный холст, на котором задачи и заметки — ноды, а связи между ними — стрелки.

Этот файл — живой документ проекта: здесь фиксируются требования, решения и прогресс по этапам. Агенты, работающие над проектом, обязаны читать его перед началом работы и отмечать выполненные пункты.

---

## 1. Принятые решения

| Тема | Решение |
|---|---|
| Платформа | Desktop, Windows в приоритете (кроссплатформенность не ломать) |
| Оболочка | **Tauri 2** |
| Бэкенд | **Rust**: доменная логика, хранилище, команды Tauri |
| Фронтенд | **TypeScript + React + Vite**, холст на **@xyflow/react (React Flow)** |
| Состояние на фронте | Zustand |
| Хранилище | **SQLite** (`rusqlite`, bundled), один файл БД в app data dir |
| Подзадачи | **Вложенный граф**: у каждой задачи свой внутренний холст, вложенность не ограничена |
| Координаты слоёв | **Общее мировое пространство**: все холсты одного пространства используют одни координаты, слой — это «плоскость над» тем же местом. Поэтому подзадачи можно показывать на основном поле там, где они лежат в своём слое |
| Вьюпорт | Один на пространство (вход/выход из слоя не двигает камеру) |
| Менеджер пакетов JS | npm |
| Слои — реализация (M3) | **Стек экземпляров React Flow**, по одному на уровень, между ними CSS-тинт (затемнение) и `filter: blur` у нижних уровней. Верхний уровень — прозрачный и интерактивный; нижние без событий и клавиатуры, повторяют камеру верхнего (`viewportBus`). Экземпляр уровня не пересоздаётся при смене роли (нет мигания) |
| Нода-родитель в слое | Рисуется верхним уровнем как «якорь» на своём месте поверх тинта; не редактируется и не двигается (драг по ней панорамирует), ПКМ — ничего, клик — выход из слоя. Хэндлы работают как начало и конец стрелки; направление стрелки всегда сохраняется таким, как её провели (v1.2: подзадача → родитель тоже допустимо, голова у родителя) |
| База знаний (v1.3) | **Настоящие .md-файлы в одной общей папке-vault** (как Obsidian, совместима с ним). Путь задаётся в настройках, по умолчанию `%USERPROFILE%\Documents\Garlic Vault`. В SQLite — только ссылка нода → относительный путь. Ноды-заметки (`kind = note`) становятся карточками .md-файлов; отдельный редактор заметок (старый M5) не делается |
| Цвет ноды (v1.2) | Заливка = цвет статуса, если он задан в настройках для этого статуса; иначе — ручной цвет из меню ноды; иначе — стандартный фон |
| Бейдж прогресса | `выполнено/всего` по задачам **прямого** вложенного холста (не рекурсивно; заметки не считаются). Нет задач — нет бейджа. Обновляется сразу при изменениях в слое |
| Просвечивание | Глубина `SEE_THROUGH_MAX_DEPTH = 3` (константа в `src/store/graph.ts`); переключатель в топбаре, хранится в `app_state.show_nested`. ПКМ по просвечивающей ноде = ПКМ по пустому месту текущего уровня; стрелку на неё бросить нельзя (как в пустое место) |
| Стек слоёв | Не сохраняется между запусками и при смене пространства — открывается корневой холст. Клик по названию пространства в топбаре — выход на корень |

## 2. Глоссарий

- **Пространство (Space)** — независимый корневой граф (например, отдельный проект). Переключается в топбаре.
- **Холст (Canvas)** — граф нод и связей одного уровня. Корневой холст принадлежит пространству, вложенный — задаче-родителю.
- **Нода** — элемент на холсте: `task` (задача) или `note` (заметка).
- **Связь (Edge)** — направленная стрелка между двумя нодами одного холста.
- **Хэндл** — точка-коннектор на стороне ноды (4 шт.: верх, право, низ, лево), из которой тянется стрелка.
- **Слой** — режим просмотра вложенного холста задачи (см. §4.5).

- **Топбар** (тонкий, минималистичный): кнопка «Пространства», справа от неё поле с названием текущего пространства, затем хлебные крошки текущего слоя; справа поиск и настройки.
- **Холст** занимает всё остальное пространство окна.

## 4. Функциональные требования

### 4.1 Холст
- Бесконечный холст: панорамирование (зажатое колесо / пробел+ЛКМ / ЛКМ по пустому месту), зум колесом.
- Положение и масштаб вида сохраняются — один вьюпорт на пространство, общий для всех его слоёв (§1).
- Фон — неброская точечная сетка.

### 4.2 Контекстное меню холста (ПКМ по пустому месту)
- «Задача» — создаёт ноду задачи в точке клика, сразу в режиме редактирования заголовка.
- «Заметка» — создаёт ноду заметки в точке клика.
- Меню минималистичное: иконка + короткая подпись, закрывается по Esc / клику мимо.

### 4.2.1 Стрелка в пустое место
- Если стрелку, потянутую из хэндла, отпустить на пустом месте холста (не на ноде), в точке отпускания открывается то же меню «Задача / Заметка».
- Выбор пункта создаёт ноду в этой точке **и сразу соединяет её стрелкой** с исходной нодой (из того же хэндла; на новой ноде — ближайшая к источнику сторона). Задача сразу в режиме редактирования заголовка.
- Пока меню открыто, рисуется «призрачная» стрелка до точки отпускания. Esc / клик мимо — отмена, ничего не создаётся.
- В слое работает так же (создаётся подзадача).

### 4.3 Ноды
**Задача:**
- Заголовок (редактируется двойным кликом по ноде, Enter — сохранить, Esc — отмена).
- Статус: `todo` / `in_progress` / `done` (клик по маркеру статуса переключает по кругу). `done` визуально приглушена/зачёркнута.
- **Цвет по статусу (v1.2):** при смене статуса вся нода заливается цветом этого статуса. Цвет для каждого статуса выбирается в настройках из палитры (8 цветов) или «нет». По умолчанию: `todo` — нет, `in_progress` — blue, `done` — green.
- **Размер (v1.2):** нода крупнее и прямоугольная — по умолчанию ~240×90 px. Заголовок переносится до 3 строк; маркер статуса и бейдж прогресса внизу/в углу. Заметка того же размера, с превью текста.
- Бейдж прогресса подзадач `выполнено/всего`, если есть вложенный холст с задачами.
- Цвет (см. 4.4).

**Заметка:**
- Заголовок + превью первых строк текста.
- Тело — `.md`-файл базы знаний (v1.3, §4.10): двойной клик по заголовку — переименование (= переименование файла), по остальной карточке — открыть заметку в режиме «База».
- Визуально отличается от задачи (иной контур/иконка).

**Общее:**
- ЛКМ + драг по телу ноды — перемещение.
- На каждой из 4 сторон — хэндл. Драг ЛКМ от хэндла к другой ноде — создаёт стрелку. Хэндлы видны при наведении на ноду.
- Выделение кликом, множественное — рамкой / Shift+клик. Delete удаляет выделенное (с подтверждением, если у задачи есть подзадачи).
- **Shift + драг ЛКМ по пустому месту (v1.2)** — рамка выделения вместо панорамирования. Без Shift ЛКМ по-прежнему панорамирует.
- **Групповые действия (v1.2):** когда выделено ≥2 нод, внизу по центру появляется плавающая панель: «Статус» (todo / in_progress / done — применяется ко всем выделенным задачам, заметки игнорируются), «Удалить» (одно подтверждение на всё, с учётом подзадач). Исчезает при снятии выделения.

### 4.4 Контекстное меню ноды (ПКМ по ноде)
Компактная горизонтальная полоса иконок рядом с нодой:
1. **Цвет** — палитра из ~8 предустановленных цветов + «сбросить». Нода **заливается целиком** выбранным цветом; цвет текста подбирается автоматически для контраста.
2. **Подзадачи** — вход в слой задачи (только для `task`).
3. **Удалить**.

(Позже можно добавить: «превратить в заметку/задачу», «дублировать».)

### 4.5 Режим слоя (подзадачи)
Ключевой визуальный эффект — «переход на слой выше»:
- По нажатию «Подзадачи» основной холст со всеми нодами **покрывается полупрозрачным тинтом и затемняется** (+ лёгкий blur), анимация ~200 мс.
- Нода-родитель **остаётся как была** — не затемняется, рисуется поверх тинта на своём месте.
- Поверх тинта открывается вложенный холст задачи: на нём ПКМ создаёт подзадачи/заметки, работают драг, стрелки, цвета — всё как на основном холсте.
- Стрелку можно протянуть между нодой-родителем и подзадачами **в любую сторону**; голова стрелки всегда там, куда её провели (хранится во вложенном холсте, см. §6).
- Выход: Esc, клик по ноде-родителю или по хлебной крошке. Анимация обратная.
- Внутри слоя у подзадачи можно снова открыть «Подзадачи» — следующий уровень. Предыдущий слой затемняется так же; хлебные крошки показывают путь.
- Открыть слой задачи также можно двойным кликом по бейджу прогресса.
- Слой открывается без сдвига камеры: подзадачи лежат в тех же мировых координатах, что видны под тинтом.

### 4.5.1 Подзадачи на основном поле («просвечивание» слоёв)
- На текущем холсте, помимо его собственных нод, отображаются ноды и стрелки **всех вложенных уровней** на своих местах.
- **Чем глубже — тем тусклее**: уровень +1 ≈ 55% непрозрачности, +2 ≈ 30%, +3 и глубже ≈ 15%. Глубина отображения ограничена настройкой (по умолчанию 3 уровня, потом скрываются).
- Такие «просвечивающие» ноды не перетаскиваются и не редактируются с текущего уровня, рисуются под нодами текущего уровня. Хэндлы на них не показываются.
- **Клик по просвечивающей ноде — «проваливание»**: сразу открывается цепочка слоёв до её холста (с той же анимацией тинта), нода выделяется. Хлебные крошки показывают весь путь.
- При наведении на просвечивающую ноду она подсвечивается и показывается тултип с путём (`Задача A › Подзадача B`).
- Правило работает на любом уровне: в слое задачи видны её подзадачи нижних уровней так же тускло.
- Переключатель в топбаре/настройках: показывать вложенные уровни или нет.

### 4.6 Пространства
- В топбаре слева — **кнопка «Пространства»**. По нажатию — выпадающая панель: список существующих пространств (клик — переключиться, текущее отмечено), поле/кнопка «+ Новое пространство», у каждого пункта — переименовать и удалить (с подтверждением).
- **Справа от кнопки — поле с названием текущего пространства.** Двойной клик по нему — переименование на месте.
- Переключение пространства сбрасывает стек слоёв и восстанавливает вьюпорт этого пространства.
- При запуске открывается последнее активное пространство.
- Последнее оставшееся пространство удалить нельзя (кнопка неактивна, Rust тоже отказывает). При удалении текущего сначала переключаемся на соседнее (следующее по списку, у последнего — предыдущее).

### 4.6.1 Обзор задач (v1.2; с v1.5/M7b — боковая панель, см. §4.12.5–4.12.6)

> **M7b:** окно с табами и деревом заменено боковой панелью у правого края (§4.12.5). Описание ниже — историческое; актуальное поведение — в §4.12.5, §4.12.6 и в записи журнала 2026-10-14.
- У правого края холста — вертикальная колонка плавающих круглых кнопок-иконок (поверх холста, не мешают панорамированию): «К выполнению», «В работе», «Готово».
- Кнопка открывает окно поверх поля (полупрозрачная подложка, окно ~60% ширины, справа или по центру) с **табами по статусам**: `К выполнению` / `В работе` / `Готово` (+ счётчики). Кнопка открывает окно сразу на своём табе.
- Таб показывает все задачи **всего текущего пространства** (все уровни) с этим статусом, **сгруппированные деревом по родителям**: путь предков показывается узлами дерева (предки с другим статусом — приглушённо, как контекст), задачи корневого уровня — в корне. Узлы сворачиваются.
- Клик по задаче — закрыть окно и «провалиться» к ней (открыть цепочку слоёв, выделить ноду, подвести камеру к ноде). Маркер статуса в строке позволяет сменить статус прямо из списка.
- Закрытие: Esc, клик по подложке, повторный клик по кнопке.
- Бэкенд: команда `list_space_tasks(space_id)` → плоский список задач с `canvas_id`, `parent_node_id`, path; дерево строится на фронте.

### 4.6.2 Настройки (v1.2)
- Шестерёнка в топбаре открывает панель настроек. Пока в ней: цвета статусов (для каждого статуса — выбор из палитры или «нет»), показ вложенных уровней. Хранится в `app_state`.

### 4.10 База знаний (v1.3)

**Хранилище (vault).**
- Одна общая папка на всё приложение; внутри — обычные папки и `.md`-файлы, никаких служебных форматов (служебное — только в SQLite). Путь меняется в настройках (можно указать существующий vault Obsidian).
- Приложение следит за папкой (watcher): изменения, сделанные снаружи (Obsidian, проводник), сразу видны в дереве, открытых заметках и на карточках нод.
- Удаление — в корзину ОС, не насовсем.

**Ссылка у ноды.**
- У **каждой ноды** (задача и заметка) **под заголовком — поле-ссылка** на папку или `.md` в базе. Изначально пустое: неброский плейсхолдер `+ база знаний`.
- Клик по пустому полю → мини-меню: **«Создать заметку»**, **«Создать папку»**, «Привязать существующее…» (поиск по базе с нечётким совпадением).
  - Имя по умолчанию — заголовок ноды (очищенный от недопустимых символов); при занятом имени — суффикс ` 2`, ` 3`…
  - Куда создаётся: папка по умолчанию из настроек (по умолчанию — корень vault).
- Заполненное поле: иконка (файл/папка) + имя. Клик → переключиться в режим «База» и открыть заметку / раскрыть папку в дереве. ПКМ по полю: «Отвязать», «Привязать другое…», «Показать в проводнике».
- **Заметка → папка.** Если к ноде привязана заметка `X.md` и выбрано «Создать папку» (пункт есть и для заполненного поля-заметки), то рядом с заметкой создаётся папка (имя — заголовок ноды), **заметка переносится в неё**, ссылка ноды теперь указывает на папку.
- Ссылки не ломаются: переименования/перемещения внутри приложения обновляют пути в БД; переименования снаружи ловит watcher (rename-событие). Если файл пропал — поле красное «не найдено» с действиями «Привязать другое» / «Отвязать».
- У ноды не больше одной ссылки; одна статья/папка может быть привязана к нескольким нодам.

**Нода-заметка.**
- Создание ноды «Заметка» сразу создаёт `.md`-файл в базе и привязывает его. Заголовок ноды = имя файла (переименование ноды переименовывает файл и наоборот). На карточке — превью первых строк файла.
- Двойной клик по ноде-заметке → открыть её в режиме «База» (по заголовку — переименовать). Новая заметка, как и задача, сразу в редактировании заголовка.
- Удаление ноды (Delete, меню ноды, групповая панель) **не трогает** файлы базы — удаляется только нода и её ссылка.
- Миграция: существующие ноды-заметки при первом запуске v1.3 выгружаются в `.md` (заголовок → имя файла, `body` → содержимое) в папку `Garlic/<пространство>/` vault (флаг `app_state.kb.notes_migrated`; колонка `body` остаётся в БД, но больше не используется).

**Режим «База» — интерфейс в стиле Obsidian.**
- Переключатель режимов в топбаре: сегмент **«Граф | База»** (Ctrl+1 / Ctrl+2). Состояние каждого режима (камера, слои / открытые вкладки) сохраняется при переключении.
- Раскладка как в Obsidian (тёмная тема Obsidian: фон `#1e1e1e`/`#262626`, акцент фиолетовый `#7f6df2`, шрифт Inter/системный):
  - узкая лента иконок слева (проводник, поиск, быстрый переход);
  - **левая панель — проводник**: дерево папок и файлов, сворачивание, «новая заметка / новая папка», переименование на месте, удаление, drag&drop перемещение, контекстное меню, сортировка по имени;
  - **центр — вкладки** открытых заметок; заголовок заметки = имя файла, редактируется над текстом;
  - **редактор**: CodeMirror 6 в режиме **Live Preview** (разметка скрыта вне строки курсора): заголовки, жирный/курсив, списки, чекбоксы `- [ ]`, цитаты, код с подсветкой, таблицы, ссылки, `[[вики-ссылки]]` с автодополнением и переходом по клику (несуществующая — создаёт заметку), переключатель «Чтение / Редактирование»; автосохранение;
  - **правая панель**: обратные ссылки (заметки, ссылающиеся на текущую) и **«Ноды графа»** — ноды, привязанные к этой заметке/папке (клик → режим «Граф», проваливание к ноде), оглавление (outline);
  - быстрый переход **Ctrl+O**, поиск по базе **Ctrl+Shift+F**.
- Граф-вид самой базы знаний (как Graph view в Obsidian) — позже.

### 4.11 Комментарий и Результат у задачи (v1.4)

**Структура ноды-задачи — три раздела сверху вниз:**
1. **Название задачи.**
2. **«Комментарий»** — ссылка на заметку или папку с материалами для решения задачи (исследования, ссылки, черновики).
3. **«Результат»** — ссылка на заметку или папку с артефактом, к которому пришли после решения.

- Оба поля ведут себя как поле-ссылка из §4.10 (пусто → клик → «Создать заметку / Создать папку / Привязать существующее»; заметка → папка с переносом; «Отвязать», «Показать в проводнике», битые ссылки). Каждое поле подписано маленькой меткой («Комментарий» / «Результат») и своей иконкой.
- Имя по умолчанию: комментарий — `<Название>`, результат — `<Название> — результат`. Папки по умолчанию для создания — отдельно для комментариев и результатов (настройки; по умолчанию `Задачи/` и `Результаты/`).
- Ноды-заметки по-прежнему имеют одну ссылку — на свой `.md` (§4.10, «Нода-заметка»).
- Существующие ссылки задач (из M5.2) при миграции становятся «Комментарием».
- В правой панели «Ноды графа» у статьи указывается роль: «комментарий к …» / «результат задачи …».

**Фильтр «Показывать только результаты» в базе знаний.**
- Галочка в шапке проводника (иконка-флажок с тултипом; состояние сохраняется).
- Когда включена, в дереве видны **только файлы и папки, привязанные как «Результат» хотя бы к одной задаче** (папка-результат — со всем содержимым), плюс папки-предки, нужные чтобы до них дойти. Всё остальное скрыто.
- У каждого результата в дереве — маленький маркер статуса задачи и тултип с её путём (`Пространство › Задача A › Подзадача B`); клик по маркеру — перейти к задаче в граф.
- Быстрый переход Ctrl+O и поиск при включённом фильтре тоже ищут только по результатам (с переключателем «везде»).
- Решено в M5.3: фильтр показывает результаты задач **в любом статусе** (константа `RESULT_FILTER_STATUSES` в `src/kb/results.ts`); маркеры статуса видны только при включённом фильтре.

### 4.12 Дерево и списки (v1.5, M7)

#### 4.12.1 Режим подсветки
- Рядом с кнопкой «показывать вложенные уровни» в топбаре — кнопка **«Подсветка»**. Включает режим, где вместо тинта/затемнения всё дерево всегда видно полностью (все уровни — обычной яркостью, без просвечивания).
- Клик по задаче выделяет **её и все её подзадачи** контрастным аутлайном (цветом акцента); остальное не гаснет.
- Включение подсветки снимает активацию с кнопки «показывать вложенные уровни» (она неактивна, пока подсветка включена).

#### 4.12.2 Выделение вместе с вложенными
- Можно выделить задачу вместе со всеми её подзадачами (всех уровней) и перетащить всю группу разом (координаты общие, поэтому подзадачи двигаются вместе с родителем).
- **Alt+клик** по задаче / **Alt+рамка** — выделение вместе со всеми вложенными; то же — пункт «Выделить с подзадачами» в ПКМ-меню ноды. Выделенные вложенные (просвечивающие) ноды подсвечиваются аутлайном.
- Настройка «Всегда двигать задачу вместе с подзадачами» (по умолчанию выкл.).
- Перемещение группы — один шаг undo.

#### 4.12.3 Удаление родителя
- При удалении задачи удаляются и стрелки от неё к подзадачам.
- Если у задачи есть подзадачи — диалог: **«Удалить подзадачи»**, **«Перенести на уровень родителя»** (подзадачи и их стрелки между собой переезжают на холст, где лежал родитель, на свои же координаты), **«Не трогать»**; затем отдельное подтверждение.
- **«Не трогать»**: подзадачи остаются в своём слое, как были (со своей вложенностью). Слой становится **«ничейным»** (`canvases.owner_node = NULL`, но это не корневой холст): на уровне бывшего родителя его ноды просвечивают как обычно, но в пунктирной рамке с подписью «без родителя»; клик — провалиться в ничейный слой (вместо якоря-родителя — пунктирная заглушка «Без родителя»). Цель — потом назначить им нового родителя.
- **Назначение родителя («Перенести в задачу…»)**: ПКМ по выделенным нодам (или по заглушке ничейного слоя — для всего слоя) → поиск задачи → выбранные ноды со своими поддеревьями и стрелками между собой переезжают во вложенный холст выбранной задачи (на свои координаты). Работает для любых нод, не только ничейных; запрещено переносить задачу в её же потомка. Пустой ничейный слой удаляется.

#### 4.12.4 Соседи по уровню
- Находясь на уровне N, видеть и другие задачи уровня N с другими родителями (не скрывать их под тинтом).
- Они рисуются над тинтом, слегка приглушённые (≈70%), с маленькой подписью родителя; стрелки их слоёв тоже видны. Не редактируются и не перетаскиваются с текущего уровня.
- **Клик по соседу — бесшовный переход** в слой его родителя (стек слоёв меняется без мигания тинта, камера не двигается), сосед выделяется.

#### 4.12.5 Боковая панель списков по статусам
- Окно обзора задач (§4.6.1) становится **вертикальной панелью у правого края**; открывается кнопкой и закрывается **только повторным нажатием той же кнопки** (не по Esc и не по клику мимо).
- Задачи — **по всем пространствам**; в шапке меню выбора пространств (по умолчанию отмечены все, выбор сохраняется).
- Вместо дерева — **прямоугольные блоки друг под другом**; вверху блока — путь `Пространство › Родитель › …`, ниже — название и статус. Блоки **перетаскиваются** — ручной порядок (очередь выполнения), сохраняется в БД.

#### 4.12.6 Закрепление списка «В работе»
- В панели «В работе» — кнопка-**канцелярская кнопка**. Когда закреплено, задачи из списка не пропадают при смене статуса на «Готово» — остаются в списке, окрашенные зелёным (мотивация «покрасить всё в зелёный»). Снятие закрепления убирает готовые.

#### 4.12.7 Статусы «Заблокирована» и «Чужая»
- Новые статусы `blocked` и `foreign`. Ставятся **только через ПКМ** (клик по маркеру статуса крутит по-прежнему только todo → in_progress → done).
- Заблокированная задача окрашена своим цветом (настраивается как остальные статусы) и несёт **«стикер»** с причиной блокировки — карточку со статусом **«Чужая»**.
- **Стикер — настоящая задача.** ПКМ → «Заблокировать…» → ввод причины → создаётся задача со статусом `foreign` (заголовок = причина), прикреплённая к углу заблокированной задачи как наклеенный стикер (чуть повёрнут, компактный, свой цвет статуса «Чужая»). Связь хранится как `blocked_by` (заблокированная → чужая).
- Когда чужая задача становится `done` или удаляется — заблокированная автоматически возвращается в предыдущий статус (тост «Разблокировано: …»). ПКМ → «Разблокировать» — снять вручную (стикер удаляется или отрывается — спросить).
- **Оторвать стикер**: драг стикера прочь от задачи превращает его в обычную ноду на том же холсте со стрелкой «блокирует» (особый стиль: пунктир, красноватая) к заблокированной задаче. Обратно — перетащить ноду на задачу.
- «Чужую» можно поставить и обычной задаче через ПКМ (чужая работа без блокировки). Статусы `blocked`/`foreign` видны во всех списках, фильтрах и обзоре; бейдж прогресса считает их как не выполненные.
- Цвета по умолчанию: `blocked` — red, `foreign` — orange (настраиваются).

### 4.7 Сохранение

- Никакой кнопки «Сохранить».

## 6. Модель данных (SQLite)

```sql
CREATE TABLE spaces (
  id          TEXT PRIMARY KEY,         -- uuid v7
  name        TEXT NOT NULL,
  root_canvas TEXT NOT NULL REFERENCES canvases(id),
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

-- Холст: корневой у пространства или вложенный у задачи
CREATE TABLE canvases (
  id          TEXT PRIMARY KEY,
  space_id    TEXT NOT NULL,
  owner_node  TEXT REFERENCES nodes(id) ON DELETE CASCADE, -- NULL для корневого
  viewport_x  REAL NOT NULL DEFAULT 0,
  viewport_y  REAL NOT NULL DEFAULT 0,
  zoom        REAL NOT NULL DEFAULT 1
);

CREATE TABLE nodes (
  id          TEXT PRIMARY KEY,
  canvas_id   TEXT NOT NULL REFERENCES canvases(id) ON DELETE CASCADE,
  kind        TEXT NOT NULL CHECK (kind IN ('task','note')),
  title       TEXT NOT NULL DEFAULT '',
  body        TEXT NOT NULL DEFAULT '',  -- markdown (заметки, описание задачи)
  status      TEXT CHECK (status IN ('todo','in_progress','done')), -- только task
  color       TEXT,                      -- ключ палитры или NULL
  x           REAL NOT NULL,
  y           REAL NOT NULL,
  width       REAL,
  height      REAL,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

CREATE TABLE edges (
  id            TEXT PRIMARY KEY,
  canvas_id     TEXT NOT NULL REFERENCES canvases(id) ON DELETE CASCADE,
  source        TEXT NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  target        TEXT NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  source_handle TEXT,  -- 'top'|'right'|'bottom'|'left'
  target_handle TEXT,
  label         TEXT
);

CREATE TABLE app_state (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

- Миграции — встроенные в бинарь, версия в `PRAGMA user_version`.
- `PRAGMA foreign_keys = ON; journal_mode = WAL`.
- v1.3 (миграция v2): `ALTER TABLE nodes ADD COLUMN kb_path TEXT` — путь относительно корня vault, разделитель `/`; папка — без `.md`. Индекс по `kb_path`. Путь vault и папка по умолчанию — в `app_state` (`kb.vault_path`, `kb.default_folder`).
- v1.5 (миграция v4, M7b): `ALTER TABLE nodes ADD COLUMN status_rank REAL` — позиция задачи в ручной очереди своего статуса (NULL — «в конец», порядок по `created_at`); триггер `trg_nodes_status_rank` сбрасывает ранг при смене статуса (задача встаёт в конец очереди нового статуса). `reorder_tasks(ids)` пишет ранги 1, 2, … в порядке `ids`. В `app_state`: `overview.hidden_spaces` (JSON-массив id снятых в панели пространств; новые отмечены по умолчанию), `overview.pinned` (JSON `{on, ids}` — закрепление «В работе»), `overview.width` (ширина панели).
- v1.4 (миграция v3, M5.3): у задачи две ссылки — роли `comment` и `result`. Хранение — колонка рядом с `kb_path`: `ALTER TABLE nodes ADD COLUMN kb_result_path TEXT` + индекс. У задачи `kb_path` = «Комментарий», `kb_result_path` = «Результат»; у ноды-заметки `kb_path` = её `.md`, `kb_result_path` всегда NULL (проверяет `repo::nodes::update`). Ссылки задач из v2 остались в `kb_path` и стали комментарием без переноса данных. `rewrite_prefix` (переименование/перемещение в приложении, rename-события watcher'а, «заметка → папка») переписывает обе колонки; `kb_linked_nodes` возвращает роль (`note | comment | result`; задача с обеими ролями на одном пути — две записи); `kb_result_links` — все результаты с задачей-владельцем для фильтра проводника. Папки по умолчанию: `kb.default_folder` (ноды-заметки, корень), `kb.default_comment_folder` (`Задачи`), `kb.default_result_folder` (`Результаты`).
- Координаты `nodes.x/y` всех холстов пространства — в одной мировой системе (см. §1). Вьюпорт пространства хранится в корневом холсте; поля вьюпорта у вложенных холстов не используются.
- Просвечивание: `load_subtree(canvas_id, max_depth) -> [{canvas, depth, path, nodes, edges, progress}]` — рекурсивный CTE по `canvases.owner_node`, уровни по возрастанию глубины, `path` — заголовки задач-владельцев от исходного холста. Сам `canvas_id` не входит; `max_depth` ограничен 16.
- Прогресс подзадач не хранится, а считается запросом: `load_canvas` и каждый уровень `load_subtree` возвращают `progress: [{nodeId, done, total}]` для задач своего холста.
- Связь между родителем и подзадачей в слое: ребро хранится во вложенном холсте, один его конец — id ноды-родителя (родитель — «якорь» этого холста), другой — нода этого холста; направление любое (v1.2: «подзадача → родитель» тоже, голова — где отпустили). Это единственный допустимый вид межуровневого ребра.

`src-tauri/src/vault/` — база знаний: `paths` (нормализация, защита от выхода за корень), `names` (очистка имён, ` 2`/` 3`), `links` (вики-ссылки, разрешение как в Obsidian), `ops` (дерево, чтение, атомарная запись, создание, переименование, перемещение, корзина, поиск, обратные ссылки), `watcher` (notify + debouncer-full, склейка «удалено + создано» в перемещение, отсев эха своих записей). `src/store/mode.ts` — режим окна, `revealGraphNode`, `openInKb`.
`src/store/history.ts` (M6a) — undo/redo графа: `installHistory()` (вызывается в `App.tsx` до рендера) подменяет действия стора графа (`createNode`, `createConnectedNode`, `connect`, `persistDelete`, `updateNode`, `queueMove` + `onNodesChange` — откуда начат драг, `setStatusMany`, `setTaskStatus`, `deleteSpace`) обёртками, которые после действия пишут шаг «отменить/повторить»; стор графа почти не тронут (добавлен `flushWrites`). **Слои (M3).** `store.layers` — стек id холстов; `enterLayer / exitTo / diveTo` грузят недостающие холсты и поддерево верхнего (`store.subtree`) и только потом меняют стек — переход атомарный. `LayerStack` рисует уровни снизу вверх: `уровень 0 │ тинт │ уровень 1 │ тинт │ … │ верхний`; у каждого свой `ReactFlowProvider`. Нижние уровни: `pointer-events: none !important`, `deleteKeyCode` и прочие клавиши `null`, обработчики из стора React Flow — `NOOP` (React Flow игнорирует `undefined` и оставил бы старые — уровень, ушедший под тинт, продолжал бы рассылать камеру). Камера: верхний уровень в `onMove` рассылает вьюпорт через `viewportBus`, нижние делают `setViewport`; новый уровень монтируется с `viewportBus.get()`; сохраняется вьюпорт в корневой холст пространства. Верхний уровень дополнительно получает «чужие» ноды (`useLayerExtras`): якорь (`type: "anchor"`, id = id родителя, поэтому стрелки «родитель → подзадача» рисуются как обычные) и просвечивающие ноды/стрелки (`type: "ghost"`, отрицательный `zIndex` по глубине, прозрачность — CSS-классы `ghost-d1..3`). Их размеры запоминаются отдельно и подставляются в `measured`, чтобы пересборка не прятала ноды до перемера. Анимации — CSS (~200 мс): тинт и проявление нод слоя при входе, обратное затухание закрываемых уровней (`leaving` в `LayerStack` держит их смонтированными на время анимации); нода-родитель на нижнем уровне скрывается с задержкой 160 мс, когда якорь уже нарисован.

**Поиск и горячие клавиши графа (M6b).** `src/search/GraphSearch.tsx` — палитра Ctrl+K / лупа в топбаре (стор `useGraphSearch`; при открытии грузит `list_graph_nodes`, `searchHits` — нечёткий отбор по названию, иначе по пути; Enter/клик → `revealGraphNode`: смена пространства, цепочка слоёв, выделение, камера). `src/canvas/hotkeys.tsx`: `CanvasHotkeys` монтируется в `FlowCanvas` только у верхнего уровня в режиме «Граф» (нужен `screenToFlowPosition`): `T`/`N` (создание в точке курсора через `createNode`, вне холста — в центре), `Tab`/`Shift+Tab` (`enterLayer` одной выделенной задачи / `exitTo(уровень выше)`), `F2` (`startEditing`), `Space` (`cycleStatus` одной задачи; несколько — `setStatusMany` со следующим статусом первой выделенной); клавиши привязаны к `e.code` (работают на любой раскладке). `keyForGraph` отсекает поля ввода, CodeMirror, кнопки вне холста, режим «База» и открытые меню/окна (`OVERLAYS`). `HotkeyHelp` — справка по `?`. Ctrl+K работает только в режиме «Граф».

Правила:
- Бизнес-логика и валидация — в Rust; фронт хранит только кэш текущих холстов.
- Типы данных между Rust и TS держать синхронными (можно генерировать через `ts-rs` / `specta`).
- Rust: `cargo clippy -D warnings` и `cargo test` зелёные. TS: `tsc --noEmit` зелёный.

## 12. Как запустить

Нужны: Rust stable-msvc (`%USERPROFILE%\.cargo\bin` в PATH), VS Build Tools с C++, Node.js, WebView2 (есть в Windows 11).

```sh
npm install
npm run tauri dev        # окно приложения с hot reload фронта
npm run tauri build      # релизная сборка + установщик
```

Проверки:

```sh
npx tsc --noEmit && npm run build
cd src-tauri && cargo clippy --all-targets -- -D warnings && cargo test
```

- БД: `%APPDATA%\com.garlic.desktop\garlic.db` (WAL). Переменная `GARLIC_DATA_DIR` подменяет каталог данных (тесты/отладка).
- База знаний: `app_state.kb.vault_path`; без него — `Документы/Garlic Vault` (создаётся при запуске). Для отладки в scratch-БД заранее записать `kb.vault_path` на тестовую папку, иначе будет создана папка в настоящих «Документах».
- Dev-сервер Vite слушает `127.0.0.1:1420` (через `localhost` Tauri на Windows его не находил).
- Отладка WebView2 по CDP: `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`.
- Второй экземпляр параллельно (порт 1420 занят): `npm run tauri build -- --debug --no-bundle` собирает `src-tauri/target/debug/garlic.exe` со встроенным фронтом (dev-сервер не нужен); запускать с отдельными `GARLIC_DATA_DIR`, `WEBVIEW2_USER_DATA_FOLDER` и своим портом CDP.
